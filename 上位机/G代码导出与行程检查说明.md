# G代码导出与行程检查

## 1. 导出到其他目录

生成窗口的“保存.ngc”和主窗口的“导出当前G代码”都可以选择桌面、其他磁盘或其他有写权限的文件夹，不再限制在上位机目录内。默认起始目录仍为`exports/`。

支持`.ngc`、`.nc`、`.gcode`、`.tap`，保存的是完整源G代码，不会自动改尺寸、位置、Z或F，也不会自动发送。配置、日志、测试与运行缓存仍写在上位机文件夹内。

## 2. 文件发送前新增的检查

导入和生成仍可离线进行。点击“开始发送”后执行以下步骤：

1. 保留现有Idle、Z基准、笔尖已抬起及G54/WCO一致性检查。
2. 自动发送只读查询`$$`，重新取得设备本次的X/Y行程`$130/$131`，不沿用旧缓存，不修改EEPROM。
3. 在后台按当前起点、G54偏移、单位和绝对/相对模式解析整个文件，将轨迹换算成机器坐标。包括进场移动、G53移动，以及圆弧中间的极值。
4. XY机器行程超限时弹窗显示文件行号、指令序号、轴、工作坐标、G54偏移和允许范围，整个任务不发送。Z仍按设备配置的独立上下界检查，超限也会弹窗拒绝。
5. 检查通过后显示开始确认窗口，用户确认后才发送任务第一行。确认时再次核对坐标、行程和设备状态；发生变化需重新检查。

查询失败、缺少或读到无效`$130/$131`时，不能跳过检查开始任务。检查期间断开、报警、软复位或查询超时都会中止本次启动，不会在恢复连接后自动启动。

目前检查适配现有STM32固件：未启用`HOMING_FORCE_SET_ORIGIN`，机器X范围为`[-$130, 0]`，Y为`[-$131, 0]`，与`$23`回零方向无关；Z使用独立配置范围。如果以后改变固件的机器坐标约定，需要同步调整上位机检查规则。

软件即使读到固件软限位关闭，也会按已读取的行程拦截越界文件。软件不会替你关闭软限位、扩大设备行程或自动修改G54。仍需按既定流程回零，保证机器坐标可信。控制台原样发送的单条命令仍使用原来的确认流程，本次新增检查针对文件任务。

## 3. 这次图片为什么会被提前拦截

当前G54为`(-192, -306, 0)`，X/Y行程为210/315mm。这时G54工作范围为X `-18～192`、Y `-9～306`，与纸张210×297mm不同。

`图片任务.ngc`的第2996行、第2995条指令为：

```gcode
G1 X193.9120 Y113.9600 F2000
```

X机器目标为`193.9120 - 192 = +1.9120mm`，超过允许的上界0。新版会在发送任何任务行之前提示这个问题，发送计数保持0。即使确认窗口默认允许开始，也不能绕过超限拦截。

## 4. 建议的验收顺序

1. 断开旧窗口串口并关闭旧窗口，再用启动脚本打开新版。
2. 先离线生成小H，在生成窗口保存到自己选择的文件夹；载入主窗口，再从主窗口导出到其他位置，确认两处均可保存。
3. 选择模拟设备，确认Z基准并抬笔。生成一个X位置195mm、宽度10mm的小任务，仍在210mm纸张内，但超过模拟器当前G54允许的工作X上界190mm。载入后点击开始，应弹窗拒绝，已发保持0，设备不会收到任务运动行。
4. 再生成X/Y各10mm、宽10mm的小任务，应通过检查并能在模拟设备中完成。
5. 真实设备按原流程建立Z基准、抬笔、XY回零和G54。G54仍为`(-192,-306,0)`且行程未变时，重新导入本次`图片任务.ngc`，点击开始，应提前提示上述第2995条指令超限，不开始绘制。
6. 在生成窗口缩小或移动图案，使全部轨迹在当前允许范围内并留余量，重新生成、载入，通过检查后再开始。

弹窗中的行号是原始文件行号；指令序号不计注释和空行，因此两者可能不同。只修改预览纸张宽度，不会改变机器可用行程。

## 5. 开发者自检

在上位机目录运行：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -q
.\.venv\Scripts\python.exe -B tests\preflight_smoke.py
```

前者覆盖坐标换算、边界、相对/英寸/G53、圆弧中间超限及无效行程；后者使用内存模拟器验证旧缓存不能放行、缺失行程拒绝、当前报警文件零任务发送、确认期间变更拦截、合法任务完成与断开中止。不存在本次图片文件时，仍执行独立的超限样例。所有测试只写本目录`.runtime/`和日志，不打开真实硬件串口。
