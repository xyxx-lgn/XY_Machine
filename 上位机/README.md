# XY写字机上位机 · 第三阶段

Python 3.11 64位 + PySide6，适配当前STM32G431 / GRBL 1.1h工程。

本版支持串口、手动控制、G代码导入、轨迹预览、逐行文件发送，以及文字/图片直接生成G代码。保留原有连续分区布局和大文件缓存。

**第三阶段的逐步操作见[第三阶段使用教程](第三阶段使用教程.md)**：先离线生成10mm高的H，再用模拟设备发送，最后按轮廓H→实心H→HOB123/中文→图片线稿的顺序实机测试。

顶部“文字生成”和“图片生成”现已开放。支持系统字体、多行文字、轮廓、轮廓＋填充、仅填充、中线、阈值/反相、尺寸位置、0.18mm直接填线间距、独立XY/Z进给及G代码导出。相邻填线只在黑色内部接续，避免跨孔洞；生成在后台进行，可以取消。

生成后只预览，点击“载入主窗口”也不会自动发送。生成器采用G54 XY和G53机器Z，不重复写G10/EEPROM；Z初值取当前设备配置，常用生成设置另存本地。中线是图形骨架，不能自动恢复手写笔顺；本版新生成任务仍只支持步进Z。

主窗口参考CoreScribe界面排布：顶部放任务操作和两条进度，左侧连续显示连接、纸张、设备控制、控制台及文件信息，右侧为可缩放轨迹和日志。没有需要切换的左侧页签；较小窗口可滚动左侧区域。

## 大文件卡顿修复（2026-11-10）

此前轨迹虽然保存成QPainterPath，位置更新时仍会重新描边整份轨迹；勾选“显示空行程”后，4万多条命令的白描文件会明显拖住界面和串口应答处理。现已改为分块绘制并缓存静态位图，周期位置更新只重画橙色标记。连续缩放/拖动时变换缓存，手势停下100ms后再重建精细轨迹；换文件、纸张或窗口尺寸变化时也会重建。

界面变化合并到每50ms刷新一次，收发状态机仍收到应答就继续发送，不等待界面刷新。文件任务只保留每500ms的状态轮询，取消每条ok附加的状态查询。日志每100ms批量更新，任务期间默认显示摘要；勾选“显示逐行收发”可恢复详细收发记录，错误与报警始终保留。

此修复没有提高G代码F值、固件速度上限或加速度，也没有修改文件轨迹或增加未确认的发送窗口。文件仍按一行一应答流控。模拟器的固定应答延时不代表实际运动耗时；真实串口和机械运动仍需实机复测。

## 启动

双击本目录中的 **启动上位机.bat**。已准备好独立的`.venv`，不需要全局安装Python包。

如果双击没有看到窗口，在本目录PowerShell中运行，以查看启动错误：

```powershell
.\.venv\Scripts\python.exe -B main.py
```

重新安装依赖可在本目录运行`安装依赖.ps1`。它只向本目录写入依赖与缓存，不修改系统执行策略。

## 先使用模拟设备

1. 串口下拉列表选择“模拟设备（不连接硬件）”，点击连接。
2. 等待状态为Idle，检查机器与工作坐标不同：WPos = MPos - WCO。
3. 勾选“已建立Z基准（勾选不清零）”。模拟器只在内存中更新坐标。
4. 点击抬笔，等待Idle；测试XY点动和读取设置。
5. 查看“设备 / Z配置”中的步进、舵机设置。
6. 点击“导入G代码”，选择`examples/阶段二小方框.nc`。导入只解析，不自动发送。
7. 点击“开始发送”，核对提示并确认。中途点击暂停，等Hold:0后点击继续；最后应显示“已确认完成”。

模拟器不模拟机械运动时间、加速度、限位或所有GRBL语义，不能替代实机验收。黄色连接横幅始终明确显示模拟状态。

## 第二阶段：第一次文件测试

1. 先完成你已验证的完整供电、Z基准、抬笔、XY回零和G54纸张原点流程。回零不会自动建立Z基准。
2. 导入你已经在Candle跑通的小H文件，先看预览的位置、比例、机器Z范围。也可用本目录10mm小方框示例，它使用Z3/-0.4和F120/240/300；只在这些值适合当前设备时使用。
3. “适配”显示整张纸，“放大图案”查看细节；滚轮缩放，按住左键拖动。蓝色为落笔XY轨迹，勾选“显示空行程”显示灰色移动。橙色十字为设备上报的实际工作坐标。
4. 点击开始前，确认Z已经抬高到手动配置的抬笔位置，状态Idle。连接初期软件自动读`$G`和`$#`；如果坐标或模态未知，可在左侧控制台重读这两项。
5. 开始前再次按当前G54和坐标检查文件，核对提示后才会发送。任务期间禁用手动运动、配置写入、换文件和控制台普通命令，实时查询/暂停/复位仍可使用。
6. 首次先用小文件完成一次，再测试暂停/继续，最后再用白描等大型文件。

**文件中的Z和F原样执行。** “设备 / Z配置”的速度、高度用于手动按钮及下次打开生成器的Z初值，不会把已载入文件里的F800改成F120，也不会把Z3.5改成Z3。要修改任务速度，请在本机生成窗口重新生成，或改Inkscape生成参数并重新导入；固件最大速度和加速度仍会约束实际运动。

**发送进度与绘制完成分开。** 已发计数代表主机写出，已应答计数代表设备回复ok。第二条进度在运行中显示等待状态，不编造绘制百分比；全部应答后仍等待连续两次Idle，才显示完成。任务按一行一应答发送，不自动重发或断点续传。大量极短线段的速度可能受串口和逐行应答影响。

暂停会立即冻结后续发送并发`!`；设备减速到Hold:0后才能继续。中止按钮先请求暂停，再确认是否发送原始`0x18`软复位；取消确认后仍保持暂停，可手动继续。中止后不会自动抬笔或返回原点，重新确认位置与Z基准后从文件开头开始。任务结束后软件自动重读模态及G54。

文件错误会显示**原文件行号**，请求暂停并锁住普通发送，检查后软复位。报警、设备重启、断开、应答超时、超过3秒无有效状态都会终止任务，不自动重发。连接状态异常时发出的暂停只是一项请求，不等于确认机械已经停止。

## 支持的G代码范围

- 直线G0/G1、XY平面G2/G3，圆弧支持增量I/J或R；原始圆弧发送给固件，预览采样不会改写文件。
- G20/G21、G90/G91、G94、G17、G54、G53、G4、G49、G92.1、G91.1，以及设置G54的Z偏移`G10 L2 P1 Z…`。文件内暂不支持改XY偏移，纸张原点使用专用按钮设置。
- M2/M30、M3/M4/M5、M7/M8/M9；含主轴/冷却输出时在开始确认中提示。
- 忽略空行、括号/分号注释和独立的`%`；支持UTF-8/GB18030注释。命令部分必须是ASCII，单行最多100字节。
- 第一次运动前文件必须明确单位、绝对/相对、G54和G94；圆弧前还需明确G17。不支持的命令会阻止导入并指出行号。

预览以X右、Y下显示，匹配当前设备。离线预览使用默认起点，第一段进场线在开始前按当前工作坐标补算。落笔线的颜色按配置抬落笔中间高度分类，仅用于预览。Z范围检查使用机器Z坐标；纸张范围只作为提示，不替代固件软限位。开始时要求当前WCO与读到的G54一致，避免未清除的G92/刀长偏移导致歧义。

现有Inkscape文件中的`G10 L2 P1 Z0`会写入设备G54的Z偏移，它不会改X/Y，但仍是EEPROM写入，开始前会明确提示。导入和分析不会修改原始文件；导入后若在其他软件修改文件，需要重新导入。

## 连接真实PCB

1. 关闭Candle、XCOM等占用同一个COM口的软件；按既有硬件流程完整供电。
2. 选择真实串口和115200，连接后先检查状态。软件只自动查询，不自动复位、解锁或运动。
3. 连接初期坐标可能显示未知。WCO是GRBL间歇返回的字段，软件会缓存后换算两种坐标，不会强改`$10`。
4. 点击读取设置，确认固件速度上限；电脑的笔参数不自动写入EEPROM。
5. 按你既有的方法建立Z机器坐标基准后，再勾选确认。该勾选不发送指令，不清零坐标，也不是Z回零。
6. 先抬笔并确认笔尖可靠离纸；等待Idle后再执行XY回零。当前`$H`使用固件已经配置好的XY回零，不包含Z。
7. 在纸张原点处使用“设置G54 XY原点”。它只设置X/Y并写入EEPROM，不修改Z。

如果设备启动处于Alarm，可在排除原因后使用解锁，再建立基准、抬笔和回零。新收到`ALARM:n`时普通发送锁定，先排除故障并软复位。解锁不能恢复失步后丢失的物理位置。

状态超过3秒未更新时禁用手动运动。普通命令应答超时不自动重发，避免重复运动。复位、断开及新报警会清除本次Z基准确认。

## 步进Z

默认抬笔2.0、落笔-0.4，抬笔进给240、落笔120。这些是起始配置，需改成你已经验证的实际参数。Z连杆坐标不是笔尖垂直毫米。

手动抬落笔发送：

```text
G21 G90 G94 G53 G1 Z目标位置 F进给
```

它使用机器Z坐标，不受工作原点影响；同时把普通G代码模态设为毫米、绝对坐标和每分钟进给。XY/Z点动使用`$J=G21 G91 ...`，不改变普通运动的坐标模式。

电脑Z边界默认-1.5到5.0，用于专用按钮和文件开始前检查，不修改固件限位。控制台原样发送的命令不做完整轨迹验证，运动相关命令会单独提示。纸张范围不等于机器的软限位范围。

## 后续切换舵机

1. 硬件及STM32固件首先切换到支持舵机的版本。
2. 在设备配置中选择舵机Z，填写固件实际支持的单行抬笔、落笔命令。
3. 确认已核实固件，保存。软件会清除旧的Z基准确认，禁用Z坐标点动。
4. 舵机模式的命令默认留空，不假定参考工程的H/V或其他私有命令一定兼容。

本阶段舵机模式可手动抬落笔，但文件通道暂时禁用。步进Z文件不能直接当成舵机任务；后续需要按实际固件协议增加转换与动作同步。

界面切换不会给STM32重新烧录。收到ok只代表命令被接受，舵机动作同步需要配套固件保证。当前Z顶部限位仅预留能力字段，未实现`$HZ`。
