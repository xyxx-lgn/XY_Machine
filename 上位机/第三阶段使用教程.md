# 第三阶段：在上位机里生成文字和图片任务

本阶段已经接通“文字/图片 → 路径 → G代码 → 预览 → 现有串口发送”。不需要先到Inkscape生成普通文字和黑白线稿；以前的Inkscape文件仍可照常导入。所有新增代码、依赖、示例和运行文件都在当前上位机目录，没有修改STM32固件或参考工程。

## 1. 启动新版

1. 先结束旧窗口里的任务，断开连接，再关闭旧窗口。
2. 双击本目录的`启动上位机.bat`。
3. 标题应显示“第三阶段”，顶部“图片生成”和“文字生成”按钮已经可以点击。
4. 当前电脑的独立环境已安装新增依赖。如果以后换电脑或重新克隆工程，在本目录执行`安装依赖.ps1`安装`requirements.txt`里的依赖。

你保存的`config/machine.json`没有被更改。生成窗口中的Z位置和速度，每次打开都会从当前设备配置读取。

## 2. 第一次先离线生成一个空心H

这一段不需要连接PCB，先看生成结果。

1. 点击顶部“文字生成”。
2. 删除示例文字，只输入大写`H`。
3. 字体选“Microsoft YaHei”或你喜欢的系统字体，先不勾粗体。
4. 路径方式选“轮廓（空心字/线稿边界）”。
5. 勾选“裁掉外围白边后设置尺寸”和“锁定宽高比例”。
6. 在“物理尺寸与位置”里设置“图案总高”为`10 mm`。宽度会根据字体比例一起改变。这里是可见图案的总高，不是字体字号。
7. 左上角X、Y均设为`10 mm`。你的纸张原点是左上角，X向右、Y向下，所以图案会放在纸张左上角向右10mm、向下10mm的位置。
8. 向下滚动左侧设置，找到“速度与步进Z”。第一次将XY绘制进给设`400 mm/min`，抬笔移动进给设`600 mm/min`，其他Z参数用你已经验证的值。
9. 点击“生成预览”。

预期现象：上方显示黑色H源图，下面显示蓝色H轮廓；O/B等字形的内部孔洞也会保留。点击“整张纸”看位置，“放大图案”看细节；滚轮缩放，按住左键拖动。

页面下方显示落笔路径数、路径点数、命令数、绘制长度、空行程和理论耗时下限。它没有计入加减速、串口等待及首次进场，不能当作实际完成时间。

生成失败时原因显示在窗口底部，例如图案超出纸张、空文字、阈值后没有图案或路径过多。修改后重新生成即可。

## 3. 在模拟设备中完整运行

1. 在生成窗口点击“载入主窗口”。窗口关闭后，主界面应出现刚才的H轨迹；这时没有发送任何运动指令。
2. 串口下拉列表选择“模拟设备（不连接硬件）”，点击连接，等待Idle。
3. 勾选“已建立Z基准”，点击“抬笔”，等待Idle。
4. 点击“开始发送”，核对文件范围和Z高度后确认。
5. 观察发送计数增长、模拟位置变化，最后应显示“已确认完成”。
6. 再执行一次，途中点击“暂停”，等待Hold:0，再点击“继续”，应接着完成。

模拟器用于检查软件流程和指令传递，不模拟真实加速度、实际笔尖高度或硬限位。不要用它的耗时判断机器写字速度。

## 4. 先用同一个H比较三种效果

每次进入“文字生成”，只改一种参数，点击“生成预览”再比较。

| 路径方式 | 纸上的效果 | 适合用途 |
| --- | --- | --- |
| 轮廓 | 沿字体边界描线，形成空心字 | 检查尺寸、位置和轮廓 |
| 仅填充 | 用蛇形线覆盖黑色部分，成为实心字 | 日常实心文字，减少重复描边 |
| 轮廓＋填充 | 描边后再填充，成为实心字 | 需要强调边缘的字，边缘会重复着墨 |
| 中线 | 提取字形骨架，以较少线条表示笔画 | 细线稿、希望减少总路径时 |

实心H建议选“仅填充”，填线间距先用你实测合适的`0.180 mm`。没有额外的“重叠比例”需要换算：这里的间距就是相邻扫描线的物理间距。墨迹太重可稍增间距，出现白缝可稍减间距；实际仍取决于笔尖宽度、纸张和速度。

填充优先把相邻行在黑色区域内接成连续蛇形线；经过字母孔洞或空白处时会断开并抬笔。它会减少不必要的抬落笔，但不会把所有文字强行连成一条线。水平、垂直填线也可以对照测试。

中线是图像骨架，不是字体数据库里的真正单线笔顺，中文、粗体和交叉位置可能出现短分叉。它不会自动恢复书写先后顺序。希望外观保持原字体时选轮廓/填充；希望线稿只描一次时再尝试中线。

## 5. 测试多行文字

1. 输入第一行`HOB 123`，第二行`写字机`。
2. 路径选“仅填充”，间距`0.180 mm`。
3. 勾锁定比例，图案总宽先设`40 mm`，X/Y都设`10 mm`。
4. 点击生成，先看HOB中的孔洞是否清晰，再看中文细笔画。
5. 载入主窗口并用模拟设备运行，然后再安排实机测试。

“总宽/总高”表示整块多行文字的包围框，不是每个字各自的尺寸。空格、换行保留，字体行距采用系统字体的默认行距。勾粗体会改变实际笔画宽度和填充量。

输入停下约300ms后会更新文字源图及宽高比例。修改任何影响路径的参数后，旧轨迹暂时保留用于对比，但“载入”和“保存”会禁用，必须重新生成，以免使用旧结果。

## 6. 测试图片生成

先使用本目录自带的`examples/阶段三线稿示例.png`，之后再用自己的白描图片。

1. 点击顶部“图片生成”，再点击“选择图片”。
2. 打开示例PNG，先用阈值`128`，不勾反相，勾裁白边和锁定比例。
3. 图案总宽设`40 mm`，左上角X/Y均设`10 mm`。
4. 先选“轮廓”生成，应该看到HOB黑色笔画的两侧边界。
5. 再选“中线”生成，应该看到较接近单条线的HOB。孔洞内部不应出现填线。
6. 再选“仅填充”生成，应该看到黑色笔画内部的蛇形线，O/B内部保持空白。
7. 确认后载入主窗口，先在模拟设备中运行。

自己的白描图建议先裁掉相框、文字水印和多余背景，使用清晰的黑线白底图片。本版读取PNG/JPG/JPEG/BMP/WEBP；SVG矢量编辑和直接导入SVG路径暂未加入，可以继续用Inkscape导出G代码或将图案导出PNG后使用。

参数含义：

- **黑白阈值**：0～255，灰度小于等于阈值的部分视为黑色。提高阈值会收进更多浅灰区域，线可能变粗；降低会排除浅灰噪点，但细线也可能消失。
- **反相**：适合白线黑底，反转要绘制的区域。
- **裁白边**：按黑色内容重新取包围框，再应用总宽/总高；取消后，尺寸包括原图外围留白。
- **简化误差**：用于轮廓和中线路径，默认0.03mm。增大会减少点数，但小细节可能改变；不是机械定位精度。填线不使用这个误差，避免简化后跨过空白。
- **忽略短于**：过滤过短的独立轮廓/中线或填线段，默认0.08mm；小数点等细小内容丢失时可调低。
- **优化路径顺序**：在局部范围内就近访问路径，并拼接端点完全重合的路径。它是速度与计算量之间的取舍，不承诺全局最短路径。

本版最长栅格边约2400像素，并显示换算后的毫米精度。大图会损失比栅格更细的细节，缩小输出尺寸或分块任务可改善。彩色照片只会按阈值成为黑白区域，暂不做灰度照片的抖动网点或艺术风格转换。

## 7. 速度到底改哪里

生成窗口分别提供四个速度，均写入生成的G代码：

| 参数 | 控制的运动 | 对应含义 |
| --- | --- | --- |
| XY绘制进给 | 落笔后沿笔画移动 | G1的F，单位mm/min |
| XY抬笔移动进给 | 从一条路径到另一条路径 | 单独的G1 F，笔已经抬起 |
| 抬笔进给F | Z从落笔到抬笔位置 | Z坐标单位/min |
| 落笔进给F | Z从抬笔到落笔位置 | Z坐标单位/min |

这些数值不是脉冲数。Z是连杆虚拟坐标，其单位不是笔尖实际垂直移动的毫米。生成器采用`G53 G1 Z… F…`控制机器Z，XY采用G54工作坐标。每次切换运动类型会明确设置F，避免Z的F串到XY，或XY的F串到Z。

实际速度仍受固件`$110/$111/$112`最大速度和`$120/$121/$122`加速度限制。上位机生成器不会修改这些设置，不会取消软限位。

调整速度后需要重新生成并载入。主窗口“设备/Z配置”的改变只影响手动按钮和下次打开生成器的初始Z参数，不会改写已经载入的文件。生成窗口里修改Z只针对本次任务，不会覆盖设备配置。

如果主要费时在抬落笔，优先比较“仅填充”与“轮廓＋填充”、水平与垂直填线，观察路径数；然后才在已验证范围内调Z行程和Z进给。不需要为使用本阶段功能去改固件参数。

## 8. 真实PCB建议按这个顺序验收

1. 结束模拟任务并断开模拟设备，确认Candle/XCOM没有占用串口。
2. 完整供电，选择真实COM口和115200连接。
3. 按你已验证的流程建立Z机器坐标基准，勾选确认，先抬笔，再XY回零，确认G54纸张原点。
4. 先运行第2节的小型轮廓H，检查位置、大小、Y方向、抬落笔和结束后离纸。
5. 再运行相同尺寸的实心H：仅填充、0.18mm，沿用已验证速度；比较实心效果和抬落笔次数。
6. 再测试`HOB 123`和一小行中文。先不要直接整页密集填充。
7. 最后用40mm示例线稿比较轮廓/中线，然后使用你自己的白描图。
8. 小任务确认后，再测试暂停→Hold:0→继续。中止后依旧需要重新确认位置与Z基准，不支持从任意行恢复。

生成任务开始时先抬笔，结束时停在最后一条路径末端并抬笔，不自动回纸张原点。点击“载入主窗口”不会开始运动。开始按钮仍使用第二阶段的检查、确认和逐行应答流程。

## 9. 保存和下次复用

- 生成窗口“保存.ngc”保存当前预览的完整G代码，不要求连接设备；保存后仍可点击载入主窗口。
- 主窗口左下角“导出当前G代码”也可导出已载入的任务；生成任务不需要先落盘才能发送。
- 默认导出目录是当前上位机目录里的`exports/`。按你的目录约束，程序拒绝向上位机目录之外写文件，也拒绝以.py/.json等扩展名保存。
- 勾“载入/保存时记住字体、尺寸和生成参数”，就会分别记住文字与图片的常用设置，下次不必像Inkscape那样重新建立定向点。
- 常用参数保存在`config/generation.json`，与`config/machine.json`分开；不保存本次Z覆盖值，下次打开仍取最新设备Z配置。不记住图片文件路径，需要重新选图。
- 这两个本地配置、`exports/`和运行缓存均默认不纳入Git。希望纳入版本管理的任务可自行复制到`examples/`再提交。

生成文件不含`G10`、`M3`和舵机私有命令，不会为每个任务重复写设备EEPROM。仍会明确设置毫米、绝对坐标、G54、XY平面和每分钟进给，清除临时G92与刀长偏移。

## 10. 当前范围和后续扩展

已实现系统字体文字、多行中文、轮廓/填充/中线、黑白图案处理、尺寸位置、独立速度、预览、导出和既有发送流程。中线不是手写笔顺生成器，理论耗时不是准确任务进度。

当前文件生成支持步进Z。切换舵机需要先确认实际STM32固件支持的命令及动作同步，再增加对应文件输出，不能只将界面改成“舵机”就直接发步进Z文件。Z顶端限位和ESP32网络通道也未在本阶段实现；生成引擎与串口层独立，后续可以复用生成结果接入新的传输方式。
