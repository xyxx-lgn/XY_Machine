# 个人笔迹：OLHWG离线轨迹扩字

这项功能解决“只录少量自己的字，离线生成没有录过的字”的问题。它使用公开的 OLHWG 多作者在线汉字轨迹模型，把你的至少15个真实录字编码成风格参考，再生成目标字的 XY 增量和抬落笔状态。生成字不是把几个部件图片粘在一起，也不是把生成结果继续当作训练样本。

## 第一次准备

在上位机目录的 PowerShell 执行：

```powershell
.\准备轨迹扩字模型.ps1
```

本机本次已经准备并实测通过，可直接打开新版上位机使用。换电脑或丢失资源时才需运行准备脚本。第一次准备需要联网下载并校验模型资源；以后扩字时不访问网络。脚本会复用或创建 `.runtime/sdt/venv`，并检查 NVIDIA CUDA；不向主界面环境安装PyTorch。两份模型约196MB，准备时另需约332MB辅助数据；若没有PyTorch，还需下载CUDA依赖。

## 使用步骤

1. 在“文字生成 → 自定义字库 / 100格采样”选择最初的真实录字字库，至少准备15个不同结构的字，建议15～30个。
2. 确认每个字已经点击“添加为新版本”或“替换当前版本”，再点击“用当前录字生成参考样本并打开AI扩展”。参考目录必须是最初真实录字导出的目录。
3. 在“扩字方式”选择“离线AI轨迹扩字：真实XY笔迹模型”。模型目录默认是 `.runtime/olhwg`，运行Python默认是 `.runtime/sdt/venv/Scripts/python.exe`。
4. 输入8～20个没有录过的字，每字版本数先用1、样式编号先用2026。点“检查轨迹模型与真实样本”，校验模型、真实录字和目标字，不执行推理；检查通过后点“离线生成个人轨迹字库”。旧偏好仍会记着原方案，需要手动选择一次新方式，之后记忆。
5. 生成完成后点击“导入本次试样到录字画板核对”，查看每个字的笔顺、分笔、连笔和字形；先关闭自然书写，用短句预览，再用小范围纸面试写。

生成阶段只使用本地模型和本地样本，不连接写字机。模型每个批次进行1000步扩散采样，因此等待时间比几何扩展长；这不会降低写字机执行速度。新字自动采用真实录字的典型占格大小，避免同一字号混排时新字比原字明显偏大。诊断文件保存在任务目录，记录生成笔数、点数、参考字和基础结构距离，距离只是结构检查提示，不是“像本人概率”。

这属于多作者预训练模型的个人参考条件推理，不是用32字从零训练一套大模型；本次不会修改原模型权重。每字1～4个候选版本，样式编号控制主要随机源；使用GPU快速卷积时，不承诺跨显卡或环境逐点完全一致。已有自然书写功能可在导入字库后继续使用。

## 继续扩展和限制

继续扩展时仍要选择最初真实录字目录，不能把 `OLHWG离线轨迹模型生成` 字库重新导出为个人样本。当前模型资源有约3755个可用字符；不支持的目标会在生成前明确报错，不会偷偷改用其他字体。已有真实录字原样保留，目标中的旧生成字会重新生成，其他已有字保留；原字库文件不会被覆盖。

模型会产生不同的笔画数量和连笔方式，因此不保证每个字与规范楷体笔顺完全一致。你提供的商家图里，一种方法明确要求录3000～6000字，另一种照片生成的内部方式和数据规模未公开；不能仅凭展示图判断它们是否完成了少样本个人扩字。本次选用的公开方案能推断未录字，但个人字形相似度和特殊合笔仍有差异。

## 直接核对这次试样

- `exports/个人笔迹_离线AI轨迹扩字试样.json`：32个真实录字原样保留，20个旧扩展字用新模型重做，总计52字。通过字库管理顶部“导入JSON”即可另存新库，不需要再等待模型。
- `exports/个人扩字_离线AI轨迹试样.png`：真实轨迹与新字的实际绘图，没有画出抬笔空移线。
- `exports/个人扩字_留出字实际对照.png`：把天、地、书、女从参考中完全排除，再禁用网络生成后的对照。它展示实际个人风格差异，不把识别正确等同为完全像本人。
- `.runtime/trajectory-learning/smoke/report.json`：真实推理、保留字、重做字、留出字、耗时、GUI回放、G代码回读和模拟设备完成记录。

推荐先导入试样，关闭“个人字库缺字用基础楷体补缺”和“自然书写”，输入“调林展其离线扩”查看新字，再混入“永木日月书”核对真实字与扩展字的大小。沿用已经确认的字号、Z基准和速度写一行小样。需要时在原字库补录不满意的字，再重新生成目标批次；也可以直接在结果库为某字添加或替换版本。

## 实现与来源

- `app/trajectory_learning.py`：真实录字校验、参考重采样、正确的Y向下坐标、按末点抬笔拆分、单点和字尾保留，以及个人占格估计。
- `tools/trajectory_model.py`：独立PyTorch推理网络；主界面不加载模型。
- `tools/sdt_adapter.py`：新方式分发、批量扩散采样、真实字优先合并、结果与诊断另存。
- `tools/prepare_trajectory_model.py`和`准备轨迹扩字模型.ps1`：固定SHA256资源准备、复用缓存和CUDA检查。
- `app/ui/sdt_dialog.py`：方式选择、模型目录记忆、后台进度、取消与导入核对；其他生成和通信流程未更改。

模型研究：[OLHWG / ICLR 2025](https://github.com/singularityrms/OLHWG)，[论文](https://openreview.net/forum?id=DhHIw9Nbl1)。兼容网络实现参考[OLHWG-PageSynth](https://github.com/HWDGRMY/OLHWG-PageSynth)，MIT许可保留于`assets/strokes/OLHWG-PAGESYNTH-MIT.txt`。权重与辅助数据来源及SHA256保存在`.runtime/olhwg/resources.json`，未作为内置字库打包分发。
